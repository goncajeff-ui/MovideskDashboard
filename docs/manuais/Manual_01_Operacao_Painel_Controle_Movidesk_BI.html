Capítulo 01

A Arquitetura do Ecossistema Movidesk BI

Funcionamento Assíncrono · Interface Blazor · SQL Server Local (MovideskDM) · Motor Extrator C#

O Painel de Controle Movidesk BI foi projetado para eliminar operações manuais em linha de comando (PowerShell/Bash), centralizando toda a infraestrutura analítica da Advice em um único executável Windows (MovideskControlPanel.exe). Sua arquitetura desacopla a interface gráfica do processamento pesado de dados por meio de três pilares integrados:

1
Camada de Apresentação Reativa (Blazor Server / Hybrid): Renderiza os cards operacionais e a automação REST API do Superset em tempo real. A thread de interface (UI Thread) nunca executa loops de rede ou banco diretamente; ela escuta eventos de estado (OnStateChanged) emitidos pelos serviços em segundo plano.
2
Motor Extrator C# Assíncrono (MovideskIngestionService): Opera estritamente dentro de Task.Run com async/await e CancellationTokenSource. Consome as APIs REST do Movidesk (/tickets, /tickets/past e /persons), respeita o Rate Limit (10 req/min em horário comercial) e valida as Procedures e Views preservando customizações manuais.
3
Data Mart Local em Microsoft SQL Server (MovideskDM): Estrutura os dados em 5 schemas especializados (raw, core, mart, ctl e sec), convertendo todos os horários UTC da API para Horário Oficial de Brasília (BRT) e servindo 9 Views analíticas aceleradas por índices covering para o Apache Superset.
Camada / Componente Tecnologia / Objeto Responsabilidade na Arquitetura
Host Desktop MovideskControlPanel.exe Aplicação .NET 8 (WinForms + Blazor WebView2) standalone com setup nativo Superset em C# via HttpClient.
Camada RAW raw.Ticket / raw.Pessoa Pouso imediato do payload JSON bruto vindo da API Movidesk via MERGE idempotente.
Camada CORE core.Fato_Ticket e Dimensões Modelo estrela normalizado pelas procedures usp_ProcessarTickets e usp_ProcessarPessoas.
Camada MART mart.vw_* (9 Views) Camada semântica de indicadores (SLA, Backlog, Aging, Throughput, Raio-X Dono Atual e Clientes por Período).
Camada CTL / SEC ctl.MarcaDagua / sec.* Controle de cursor incremental, auditoria de lotes (ctl.ExecucaoCarga) e segurança por equipe.

Capítulo 02

Launcher & Setup Automático do Apache Superset

Acionamento Silencioso via WSL2 e Provisionamento REST API Nativo em C# (Porta 8088)

Além de subir e monitorar o Apache Superset no WSL2 (Ubuntu) via System.Diagnostics.Process com CreateNoWindow = true, a classe SupersetService conta com o card Configuração Inicial do Superset: um motor 100% nativo em C# (HttpClient) que cria a conexão MovideskDM, registra as 9 Views mart e publica automaticamente o Dashboard - Movidesk BI (15 gráficos e filtros globais) sem precisar abrir terminal.

1
Subir o Servidor (Botão "Iniciar Superset (WSL2)"): Ao clicar no botão azul primário, o status muda imediatamente para Subindo servidor... com um spinner visual. Internamente, o C# dispara wsl.exe -d Ubuntu -- bash -lc "source ~/superset-env/bin/activate && nohup superset run -h 0.0.0.0 -p 8088 ...".
2
Sondagem Automática de Saúde (Health Check HTTP): Enquanto o servidor inicializa, o painel executa requisições assíncronas a cada 2 segundos para http://localhost:8088/health. Assim que o Superset responde HTTP 200 OK, o badge superior fica verde (Online).
3
Acesso Rápido e Setup 1-Clique ("Executar Setup Automático" e "Abrir Dashboard Movidesk ↗"): Com o servidor Online, informe a senha do admin e clique em Executar Setup Automático para criar ou atualizar os 9 Datasets, 15 gráficos e os filtros nativos (Equipe, Serviço e Período), acessando direto /superset/dashboard/dashboard-movidesk/.
4
Encerramento Limpo ("Parar Superset"): Caso seja necessário reiniciar o serviço, o botão vermelho encerra os processos do Superset/Gunicorn dentro do WSL2 de forma segura e retorna o indicador para Offline.
Botão / Indicador Estado Visual Comportamento Técnico Executado pelo Painel
Iniciar Superset (WSL2) Subindo servidor... Dispara o comando bash no WSL2 em background e inicia o polling HTTP até a porta 8088 responder.
Executar Setup Automático Concluído Executa em C# nativo a REST API do Superset para criar MovideskDM, 9 Datasets, 15 Gráficos e 3 Filtros Nativos.
Abrir Dashboard Movidesk ↗ Online Abre o navegador diretamente em http://localhost:8088/superset/dashboard/dashboard-movidesk/.
Parar Superset Offline Envia pkill -f "superset|gunicorn" via WSL2 para liberar memória e encerrar a instância ativa.

Capítulo 03

Monitor de Volumetria em Tempo Real (MovideskDM)

Auditoria via Dapper · Contagem de core.Fato_Ticket · Vínculo de Empresas e Snapshot Histórico

O módulo 2. Monitor de Volumetria (MovideskDM) utiliza o micro-ORM Dapper (DatabaseMonitorService) sobre conexões assíncronas SqlConnection para consultar em tempo real o estado do Data Mart no SQL Server. Com a chave Auto-refresh (5s) habilitada, o operador acompanha a evolução da base lote a lote sem precisar atualizar a página manualmente.

1
Indicador Principal (SELECT COUNT(*) FROM core.Fato_Ticket): O número em destaque no topo do card mostra exatamente quantos chamados já foram extraídos, normalizados em Horário de Brasília (BRT) e gravados na tabela fato principal core.Fato_Ticket, prontos para leitura imediata pelos gráficos do Apache Superset.
2
RAW Total vs. Empresas / Contatos Vinculados: O minicard esquerdo exibe o total bruto em raw.Ticket, enquanto o minicard direito audita a separação entre Empresas Clientes (TipoPessoa IN (2, 4)) e Contatos Vinculados (pessoas físicas associadas às suas respectivas organizações em core.Dim_Cliente).
3
Faixa de Tickets (#ID) e Fronteira Histórica / Snapshot: Exibe o menor e o maior protocolo/ID presentes no banco (ex.: #335 → #55297), a data UTC exata onde a carga regressiva histórica está posicionada e a quantidade de dias populados na tabela de evolução de fila (core.Fato_SnapshotBacklog, ex.: 91d).
Métrica no Card Consulta SQL Executada (Dapper) Finalidade Operacional e de Negócio
Chamados no Data Mart SELECT COUNT(*) FROM core.Fato_Ticket Confirma o volume total de tickets disponíveis nas 9 Views analíticas (mart.vw_*).
RAW Total SELECT COUNT(*) FROM raw.Ticket Total de payloads JSON brutos armazenados na camada de pouso antes/após o processamento.
Empresas / Contatos COUNT(*) FROM core.Dim_Cliente Garante que as visões de Churn e Saúde de Clientes (vw_ClienteRaioX e vw_TicketsPorClientePeriodo) agrupem por Empresa real.
Faixa de Tickets (#ID) MIN(TicketId) / MAX(TicketId) Mostra a amplitude histórica de protocolos já cobertos pela base analítica.
Fronteira / Snapshot LEAD(LastUpdateUtc) + Fato_SnapshotBacklog Indica o ponto exato de retomada da carga histórica e os dias de histórico da curva de backlog.

Capítulo 04

Orquestrador de Carga de Dados (Anti-Travamento)

Carga Histórica (Skip e Cursor Inteligente) · Carga Incremental Assíncrona · Sincronização de Empresas

A carga histórica da API do Movidesk envolve dezenas de milhares de chamados com histórico de status e campos customizados. Para evitar qualquer congelamento da janela desktop, o Orquestrador de Carga de Dados executa todo o pipeline de rede e banco em uma thread isolada via Task.Run, atualizando o console visual a cada etapa ("Extraindo...", "Salvando no Banco...", "Processando Core...", "Aguardando Rate Limit..." e "Concluído").

1
Carga Histórica (Paginação $skip + Cursor Regressivo Inteligente): Ao acionar "Disparar / Retomar Carga Histórica", o motor verifica primeiro o estado do banco. Se a base estiver vazia, pagina a partir de skip = 0 (ou do skipInicial parametrizado) em lotes de 50 registros. Se a base já possuir chamados salvos, ele detecta automaticamente a Fronteira Histórica UTC (lastUpdate le {cursorUtc} com skip = 0), pulando instantaneamente os milhares de tickets já importados sem desperdiçar requisições.
2
Carga Incremental Assíncrona (Marca d'Água): Ao clicar em "Disparar Carga Incremental", o extrator lê a última data gravada em ctl.MarcaDagua (aplicando margem de segurança de -10 minutos), busca apenas os chamados novos ou alterados recentemente ($filter=lastUpdate ge ...), processa o modelo estrela e atualiza o snapshot diário em segundos.
3
Sincronizar Empresas (/persons) e Cancelamento Seguro: O botão "Sincronizar Empresas (/persons)" importa todas as organizações (personType eq 2) e resolve o vínculo de empresa dos contatos já presentes nos chamados via core.usp_ProcessarPessoas. O botão "Cancelar Carga" interrompe o lote atual com segurança, preservando 100% do progresso já salvo.
Operação no Painel Estratégia de Paginação / Filtro API Resultado no Banco MovideskDM
Carga Histórica Fase 1 (Delta recente) + Fase 2 (/tickets/past com lastUpdate le {cursor} e $skip dinâmico) Importa todo o passivo histórico com contadores separados de +Novos Inseridos vs. Atualizados.
Carga Incremental /tickets?$filter=lastUpdate ge {MarcaDagua - 10min}&$orderby=lastUpdate asc Atualiza a fila ativa, recalcula SLA/Aging em Horário de Brasília e renova ctl.MarcaDagua.
Sincronizar Empresas /persons?$expand=relationships (Empresas personType eq 2 + lotes de 15 contatos) Popula raw.Pessoa e vincula retroativamente core.Fato_Ticket.EmpresaId à Organização real.
